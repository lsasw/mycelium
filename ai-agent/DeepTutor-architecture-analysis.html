📋 项目概述

DeepTutor 由香港大学数据智能实验室开发，定位为 "agent-native learning workspace"。

设计哲学

DeepTutor 核心理念是 "一个运行时，多种模式" — Chat、Quiz、Research、Visualize、Solve、Mastery Path 都运行在同一个智能体循环之上。系统采用 两层插件模型：

  • L1 — Tools（工具层）：单次调用的功能工具，LLM 按需选择
  • L2 — Capabilities（能力层）：多阶段管道，接管完整的对话回合

⚡ 调用链路

一次用户请求的完整调用路径

1

入口接收

CLI: deeptutor chat / WebSocket: /api/v1/ws / SDK: DeepTutorApp.handle() → 构造 UnifiedContext

2

Orchestrator 路由

ChatOrchestrator.handle(context) → 检查 context.active_capability，默认使用 chat 能力

3

Capability 初始化

从 CapabilityRegistry 获取对应能力实例，创建 StreamBus，注册 turn_id

4

能力管道执行

capability.run(context, bus) → 通过 bus.stage() 声明阶段边界，内部调用 LLM + 工具

5

Agent Loop (Chat 能力内部)

LLM 推理 → 决定调用工具 → ToolRegistry.execute(name, args) → 观察结果 → 继续推理，直到生成无工具调用的最终回复

6

流式事件分发

每条 StreamEvent (CONTENT, TOOL_CALL, TOOL_RESULT, STAGE_START/END...) 通过 StreamBus fan-out 到所有订阅者

7

消费者渲染

CLI: Rich 终端渲染 / WebSocket: NDJSON 推送到前端 / SDK: 返回 AsyncIterator

8

完成与审计

发送 DONE 事件，发布 CAPABILITY_COMPLETE 到全局 EventBus，触发审计日志、记忆合并等后置处理

🚀 核心功能实现

1. Ask-User 机制

智能体在对话中暂停回合，提出结构化澄清问题，等待用户回答后继续同一回合。

# 工具返回 pause_for_user 标记
return ToolResult(
    content="Which topic should I focus on?",
    pause_for_user={"question": "...", "options": [...]}
)
# Chat 循环检测到此标记后：
# 1. 发送 pending_user_input 事件
# 2. await 用户回复 (通过 reply queue)
# 3. 将回复替换到工具消息体中
# 4. 继续同一轮 LLM 迭代

2. 多引擎 RAG 知识检索

支持 5 种检索引擎，通过统一接口切换：

引擎特点适用场景
LlamaIndex本地 FAISS 向量 + BM25 混合默认引擎，通用场景
PageIndex托管推理检索，页级引用精细引用溯源
GraphRAG知识图谱检索关系型知识发现
LightRAG轻量级图谱检索 + 外部服务器低资源部署
Obsidian链接 Obsidian 保险库，原位读写个人知识管理集成

3. 三层记忆系统

层级名称存储说明
L1事件追踪JSONL 仅追加工作区镜像 + 事件流，记录 chat/notebook/quiz/kb/book/partner/cowriter

记忆图谱可视化整个金字塔结构，任何合成声明可追溯到原始事件。

🔄 Agent 循环机制

Chat 能力的智能体循环

①

构建 Prompt 上下文

组装 system prompt (memory_context + persona_context + skills_manifest + source_manifest + i18n 模板) + conversation_history + user_message

②

组装工具列表

合并用户开关工具 (brainstorm/web_search/paper_search/reason) + 上下文自动挂载工具 (rag/read_memory/web_fetch...) + MCP 工具 + 延迟工具条目

③

LLM 推理 (Streaming)

调用 LLM SDK (OpenAI/Anthropic/DashScope/Perplexity)，通过 bus.content() 流式输出 CONTENT 事件

④

工具调用检测

如果 LLM 返回 tool_calls：通过 bus.tool_call() 发出事件 → ToolRegistry.execute() 执行 → 通过 bus.tool_result() 返回结果 → 将结果追加到对话历史 → 回到 ③ 继续推理

⑤

用户交互暂停 (Ask-User)

如果工具返回 pause_for_user：暂停循环 → 等待前端/CLI 回复 → 将回复注入 → 继续循环

⑥

结束条件

LLM 返回不含工具调用的纯文本回复 → 通过 bus.result() 发送最终结果 → 发送 DONE 事件 → 保存会话、更新记忆

设计要点：Chat 是默认能力，Deep Solve、Quiz、Research、Visualize 等能力在 Chat 循环的基础上叠加阶段层（stage）管理，通过 bus.stage() 声明多阶段边界，但内核仍是同一个 LLM + Tool 迭代循环。

📝 架构总结

架构优势

✅ 高度可扩展

工具和能力通过注册表模式实现插件化，新增功能只需实现接口。MCP 协议支持外部工具无缝接入。

✅ 流式优先设计

StreamBus 实现了生产者/消费者解耦，同一事件流可同时供给 CLI、WebSocket、SDK 三种消费端。

✅ 全异步架构

asyncio 贯穿全栈，从 LLM API 调用到文件 IO、WebSocket 通信都使用原生 async/await。

✅ 模块化设计

pip extra 机制实现按需安装，75 个第三方包根据使用场景分级引入。

✅ 安全优先

沙箱代码执行、SVG 验证、MIME 检查、PDF 大小限制、bcrypt 密码哈希、JWT 认证。

✅ 国际化就绪

能力提示词和 UI 支持中英文，YAML 模板化，易于扩展新语言。

💡 学习要点

可以从 DeepTutor 学到什么

  1. 插件化架构设计 — 通过抽象基类 + 注册表实现高度可扩展的工具/能力系统
  2. 流式事件总线模式 — 生产者/消费者解耦，同一数据流多端消费
  3. 全异步 Python 编程 — asyncio + AsyncIterator + Queue 构建高性能 IO 密集型应用
  4. 多引擎策略模式 — RAG / 文档解析 / LLM Provider 统一接口下的可插拔实现
  5. LLM Agent 循环实现 — Tool Calling → 观察 → 推理 → 再调用的完整循环
  6. Python dataclass 协议设计 — 用数据类而非字典传递结构化数据
  7. 现代化 Python 项目治理 — pyproject.toml + Ruff + Black + MyPy + Bandit 完整工具链
  8. 渐进式安全设计 — 沙箱隔离、输入验证、认证授权分层实现
  9. CLI + Web + SDK 三入口统一 — 共享核心逻辑，入口层只做适配
  10. 多语言 i18n 实践 — YAML 模板化提示词，能力层与 UI 层解耦语言
