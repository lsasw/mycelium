01

项目概述

WeKnora 是腾讯开源的 LLM 知识管理框架，面向企业级文档理解、语义检索与智能推理场景，2025 年 8 月立项、持续活跃迭代至今。

一句话定位

WeKnora 将原始文档沉淀为三类可消费的知识资产：RAG 问答库（可查询）、自主推理智能体（可推理）、自维护 Wiki（可自动演进）。它不是单点工具，而是覆盖「文档解析 → 知识组织 → 检索问答 → 智能体编排 → 图谱演化」全链路的开源知识平台。

⚡

RAG 快速问答 CORE

语义 + BM25 混合检索，答案自动标注来源，规避 AI 幻觉；支持父子分块、GraphRAG 图谱增强、重排序与引用浮层。

🧠

ReAct Agent 推理 CORE

渐进式多步推理，自主编排知识检索、MCP 工具调用与网络搜索；支持人机审批节点与自定义智能体配置。

🗂️

AI 自动 Wiki v0.5+

Agent 从原始文档自动蒸馏为结构化、互链的 Markdown Wiki 页面与可视化知识图谱，支持万级文档规模持续更新。

WeKnora 采用「前端多端接入 + Go 模块化后端 + 可插拔存储/模型层」的分层架构。以下从整体分层、RAG 流水线、Agent 推理循环三个视角拆解。

03

主要功能模块说明

从仓库 internal/、frontend/src/、docreader/、mcp-server/ 等目录反推出的六大核心功能模块。

📄 模块 A · 文档解析引擎（docreader + anydoc）

WeKnora 最具技术含量的一层。anydoc 是 Rust 编写的文档解析库，通过 cgo 以静态库方式链接进 Go 进程，无需独立解析服务即可在进程内把 Office 文档转换为带原位图片的 Markdown。

格式解析方式要点
DOCX / PPTX / XLSXanydoc（Rust）保留原位图片，转换为结构化 Markdown
PDFanydoc + OCR 回退恶意 PDF 解析开销设上限防 CPU 耗尽；扫描版回退 DocReader OCR
XMindXMind 大纲解析同时支持现代与经典 XMind 档案格式
Markdown / HTML / EPUB / MHTML / 图片 / CSV / JSON内置解析器网页剪藏、RSS、GitLab 等多源文档统一入口
飞书文档blocks API / export APIFEISHU_DOCX_PARSE_MODE 控制双路径
✅
设计亮点：Rust 静态库通过 cgo 链入 Go 进程（third_party/anydoc-go/），避免独立解析服务带来的部署与运维成本，同时获得 Rust 的内存安全解析能力 —— 这是项目「模块化但不微服务化」哲学的代表作。

📚 模块 B · 知识库管理（internal/models + frontend）

核心能力

  • 三种知识库类型：FAQ / 文档 / Wiki，支持文件夹导入、URL 导入、多标签管理
  • 文件夹树：上传保留原始目录结构，树形浏览、重命名与重新归档
  • 分块编辑与版本历史：可视化编辑检索分块，逐版本 diff 与回滚，自动重建索引
  • 文档摘要：支持手动编辑与 LLM 自动生成（PR #2752）
  • 批量操作：框选多选、批量重新解析、批量打标签

对应前端组件（Vue 3）

  • KnowledgeBase.vue —— 知识库主视图
  • DataSourceEditorDialog.vue —— 数据源配置编辑器
  • 分块分页状态管理组件（chunk pagination 专项加固）
  • Markdown 预览渲染器隔离（防 XSS 渲染隔离）

🔍 模块 C · 混合检索系统（RAG）

检索层采用多路召回 + 统一规范化 + 重排序的现代 RAG 架构：

  • BM25 稀疏召回 —— 精确关键词匹配，处理专有名词与代码片段
  • Dense 稠密召回 —— Embedding 语义相似度，pgvector HNSW 加速（1024 维）
  • GraphRAG 图谱增强 —— 知识图谱实体关联补充召回（chunk + 实体并行）
  • 父子分块 —— 小块检索 + 大块上下文补全
  • MMR 增量去重 —— agent 检索中的多样化选择（perf 专项优化）
  • MatchCount 规范化 —— 修复 match_count 遗漏导致的空集与负值 500 问题
检索维度机制用途
chunk 检索向量 + 倒排混合常规语义问答
实体检索知识图谱实体遍历关系型问题、多跳推理
FAQ 检索FAQ 专用索引高频标准化问题
父块补全父子分块映射长上下文完整性

🤖 模块 D · ReAct Agent 与工具生态（internal/agent + sandbox + mcp）

渐进式推理

Thought → Action → Observation 循环，自主规划多步任务，最多 N 轮迭代，RAG 进度分阶段可视化展示。

工具调用

内置工具（知识检索/读文档）+ MCP 工具（含 OAuth2 远程服务）+ 网络搜索，支持 @Skill / @MCP 提及范围化运行时。

沙箱执行

按空间配置 E2B / Cube 远程沙箱，提供 shell_exec、文件管理、Artifacts 收集；模板状态/凭据/超时可解释诊断。

人机审批

工具调用可设审批节点，关键操作人工确认，适配企业合规场景。

跨会话记忆

长期记忆（memory）模块，跨会话沉淀用户偏好与上下文，事件驱动（internal/event）。

临时附件

会话级上传图片/文档，后台异步解析，一次性问答，可配置 TTL 过期清理，不入库。

🔌 模块 E · 数据源连接器体系（internal/datasource）

以泛型流式同步引擎（engine.go）为统一底座，不同连接器差异通过 NodeOps 适配器隔离，实现增量同步、失败不推进游标、断点快照（toSyncCursor）等一致语义。

🏢 模块 F · 平台治理与安全（system-admin + ratelimit + tracing）

  • 空间 RBAC 四级角色矩阵：Owner / Admin / Contributor / Viewer，按知识库资源归属管理；跨空间超级管理员；每空间审计日志
  • 平台级 API Key：capability-based 访问控制，权限范围可裁剪（Principal 模型）；凭据 AES-256-GCM 静态加密
  • 多租户术语：用户可见 tenant 统一重构为 workspace，简化心智模型
  • 安全防线：gRPC TLS、SSRF 出站白名单加固（MCP 专项）、密码策略 8–32 位、随机密码幂等创建
  • 可观测性：Langfuse 追踪（ReAct 循环 / Token / 工具调用）、运行时任务队列面板、系统管理员创建审计事件
04

技术实现要点解析

深入代码风格与工程实践层面，提炼 6 个值得学习的实现要点。

🦀
Rust + cgo：进程内高性能文档解析 anydoc 以 Rust 静态库形式通过 cgo 链入 Go 进程（third_party/anydoc-go/），替代独立的解析微服务。收益：零网络开销、部署极简；代价：交叉编译与发布需处理 cgo 工具链 —— 项目在 CI 中维护了对应矩阵。这是「性能敏感件用 Rust，业务件用 Go」的经典混合范式。
⚙️
泛型流式连接器：StreamingConnector + NodeOps 数据源同步统一为流式引擎：resume fast-path（续传加速）、failure-does-not-advance-cursor（失败不推进游标）、toSyncCursor 快照语义。新增数据源只需实现 NodeOps 适配器，同步语义零成本复用 —— 连接器从「各自为政」收敛为「单一引擎 + 适配器」。
📐
多模块 Go 工程：每模块独立 go.mod 主仓库含多个 Go module（核心服务 / client / cli / mcp-server 等），CI 矩阵逐模块执行 lint 与测试。配合 .air.toml 热重载实现快速开发模式，前端 Vite HMR 与后端 Air 并行 —— 仓库级 monorepo 同时服务「单一代码库」与「独立发布」两个诉求。
🧪
三层测试体系 + 契约测试 单元测试（函数级）、API 契约测试（前后端接口固定，如 dsh-weknora 插件的 Go 契约测试）、端到端测试（tests/）。契约测试是前后端并行开发的粘合剂，保证接口演进不破坏既有消费方。
🛡️
安全纵深：从密钥到出站请求 三层防御：静态层（AES-256-GCM 加密 API Key 与第三方凭据）、传输层（gRPC TLS）、行为层（SSRF 出站白名单 + 恶意 PDF 解析开销上限 + 沙箱隔离）。尤其值得学习的是「资源开销设上限」的思路 —— 不信任输入，对解析复杂度做显式 bound。
🌐
前端工程：Vue 3 + TDesign + Vite + i18n TypeScript monorepo（pnpm workspaces），TDesign 组件库 + 自定义 theme.css 覆盖 token（生产构建保留自定义主题）；i18n 支持中/英/日/韩/俄五语言，DEFAULT_LOCALE 运行时配置 + locale 白名单防注入；TDesign 图标本地打包保障离线/内网部署；nginx 镜像固定 digest 兼容 CentOS 7 等旧内核主机 —— 每一条 fix 都是真实生产踩坑的沉淀。
GO · 混合检索核心语义（简化还原）
// internal/agent 中检索深度统一为常量
const DefaultRetrievalTopK = 50

// 混合检索：chunk 与实体并行召回后统一规范化
func HybridSearch(ctx context.Context, q string) ([]Chunk, error) {
    ch, err := searchChunks(ctx, q)    // BM25 + Dense + Graph
    ent, err := searchEntities(ctx, q)  // 图谱实体召回
    return normalizeMatchCount(merge(ch, ent)), nil // MatchCount 规范化
}

// Agent 侧：MMR 增量选择，去重且保持多样性
func SelectWithMMR(cands []Chunk, k int) []Chunk {
    return incrementalMMR(cands, k) // perf(agent): 增量而非全量重算
}

代码风格与工程实践

  • gofumpt / gofmt 预提交钩子强制统一格式

  • 语义化提交：feat / fix / perf / refactor / chore / docs 前缀，PR 编号跟踪（如 #2722）

目录组织

  • 后端：cmd/ 入口 + internal/ 业务 + third_party/ 三方绑定 + migrations/ 版本化迁移
  • 前端：frontend/src/{api,config,router} + packages monorepo

快速上手与部署形态

🚀 Docker Compose 一键启动

BASH
# 1. 克隆仓库
git clone https://github.com/Tencent/WeKnora.git
cd WeKnora

# 2. 配置环境变量
cp .env.example .env

# 3. 启动（默认核心服务 / 可选 profile）
docker compose pull
docker compose up -d
# 可选：docker compose --profile full up -d
#      docker compose --profile neo4j up -d  （知识图谱）
  • Web UI → http://localhost
  • 后端 API → http://localhost:8080
  • Langfuse → http://localhost:3000
