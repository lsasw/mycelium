Vue 基础 —— 响应式数据、模板语法、计算属性、侦听器

难度：★★☆☆☆

1.1 创建 Vue 应用与响应式数据

Vue 3 使用 createApp 创建应用实例，ref() 和 reactive() 创建响应式数据。ref 用于基本类型，通过 .value 读写；reactive 用于对象，直接读写属性。

HTML + JS 
<div id="app">
  <!-- ref 在模板中自动解包，无需 .value -->
  <p>计数：{{ count }}</p>
  <button @click="count++">+1</button>
  <button @click="count--">-1</button>
  <!-- reactive 对象直接访问属性 -->
  <p>用户：{{ user.name }}，年龄：{{ user.age }}</p>
  <button @click="user.age++">长大一岁</button>
</div>
<script type="module">
  import { createApp, ref, reactive } from 'vue'
  createApp({
    setup() {
      const count = ref(0)           // 基本类型用 ref
      const user = reactive({        // 对象用 reactive
        name: '小明',
        age: 18
      })
      return { count, user }         // 暴露给模板
    }
  }).mount('#app')
</script>

1.2 计算属性 computed

计算属性会缓存结果，只有依赖的响应式数据变化时才重新计算。相比方法，computed 不会在每次渲染时重复执行，性能更好。

JS 
import { ref, computed } from 'vue'

const price = ref(100)           // 单价
const quantity = ref(2)          // 数量

// 计算属性 —— 自动追踪 price 和 quantity
const total = computed(() => {
  console.log('computed 重新计算了')  // 只在依赖变化时触发
  return price.value * quantity.value
})

// 只读：total.value = 300  // ❌ 报错！计算属性默认只读

1.3 侦听器 watch

watch 用于在数据变化时执行副作用（如 API 请求、DOM 操作、存储数据）。与 computed 不同，watch 不返回新值，而是执行操作。

JS 
import { ref, watch } from 'vue'

const keyword = ref('')
const results = ref([])

// 侦听 keyword 变化，模拟搜索
watch(keyword, async (newVal, oldVal) => {
  if (newVal.trim() === '') {
    results.value = []
    return
  }
  // 模拟 API 请求（实际项目用 fetch/axios）
  await new Promise(r => setTimeout(r, 300))
  results.value = [
    newVal + ' 的结果 A',
    newVal + ' 的结果 B'
  ]
})
ⓘ
ref vs reactive 怎么选？
单个基本类型用 ref；一组关联数据用 reactive；不确定就用 ref（更通用）。模板中 ref 自动解包，但 JS 中必须 .value。

核心指令详解 —— v-bind、v-model、v-for、v-if/v-show

难度：★★☆☆☆

2.1 v-bind —— 动态绑定属性

v-bind 将 HTML 属性与 JS 表达式绑定，简写为 :。可以动态控制 class、style、src、href 等任何属性。

HTML 
<!-- 完整写法 -->
<img v-bind:src="imageUrl" />
<!-- 简写（推荐） -->
<img :src="imageUrl" />
<!-- 动态 class -->
<div :class="{ active: isActive, 'text-danger': hasError }"></div>
<!-- 动态 style -->
<div :style="{ color: textColor, fontSize: size + 'px' }"></div>

2.2 v-model —— 双向数据绑定

v-model 是 Vue 中最常用的指令之一，自动完成"数据 → 视图"和"视图 → 数据"的双向同步。适用于 input、textarea、select 等表单元素。

HTML 
<!-- 文本输入 -->
<input v-model="username" placeholder="输入用户名" />
<p>你输入的是：{{ username }}</p>

<!-- 复选框 -->
<input type="checkbox" v-model="agree" /> 同意协议

<!-- 多选复选框 -->
<input type="checkbox" v-model="hobbies" value="篮球" /> 篮球
<input type="checkbox" v-model="hobbies" value="游泳" /> 游泳

<!-- 下拉选择 -->
<select v-model="city">
  <option value="">请选择</option>
  <option value="beijing">北京</option>
  <option value="shanghai">上海</option>
</select>

2.3 v-for —— 列表渲染

v-for 遍历数组或对象来渲染列表。必须搭配 :key 使用，帮助 Vue 追踪每个节点的身份，高效更新 DOM。

HTML 
<!-- 遍历数组 -->
<li v-for="(item, index) in todoList" :key="item.id">
  {{ index + 1 }}. {{ item.text }}
</li>

<!-- 遍历对象 -->
<li v-for="(value, key, index) in userInfo" :key="key">
  {{ key }}: {{ value }}
</li>

<!-- ⚠️ v-for 和 v-if 不要同时用在同一元素上！ -->
<!-- 正确做法：用 computed 先过滤，再 v-for -->
⚠
注意：v-for 和 v-if 不要写在同一元素上！v-if 优先级高于 v-for，会导致性能问题。正确做法是先用 computed 过滤数据，再 v-for 渲染。

2.4 v-if vs v-show —— 条件渲染

v-if 是"真正的"条件渲染——不满足条件时元素根本不会被创建。v-show 只是切换 display:none，元素始终存在于 DOM 中。

特性v-ifv-show
DOM 操作条件为 false 时不渲染元素始终渲染，只切换 display
切换开销高（销毁/重建）低（只改 CSS）
初始开销条件为 false 时零开销始终有初始渲染开销
适用场景切换频率低的情况频繁切换的情况
可与 v-else 配合可以不可以

组件化开发 —— 注册、Props、事件、插槽

难度：★★★☆☆

3.1 组件注册与 Props 传参

组件是 Vue 的核心概念——把 UI 拆成独立可复用的小块。父组件通过 Props 向子组件传递数据，Props 是单向数据流（父→子，子不能直接修改）。

JS 
// 子组件
const ChildCard = {
  props: {
    title: { type: String, required: true },   // 必传
    count: { type: Number, default: 0 },        // 有默认值
  },
  template: `
    <div class="child-card">
      <h4>{{ title }}</h4>
      <p>数量：{{ count }}</p>
    </div>`
}

// 父组件使用
app.component('child-card', ChildCard)
// <child-card title="购物车" :count="10" />
✔
最佳实践：Props 应详细定义类型、默认值和是否必传。这既是文档，也能在开发阶段提供警告。

3.2 emit —— 子组件向父组件通信

子组件通过 $emit 向父组件发送事件，父组件用 @event-name 监听。这是 Vue 中实现"子→父"通信的标准方式。

JS 
// 子组件：触发事件
const Counter = {
  props: ['value'],
  emits: ['update:value'],    // 声明要触发的事件（推荐）
  template: `
    <div>
      <button @click="$emit('update:value', value - 1)">-</button>
      <span>{{ value }}</span>
      <button @click="$emit('update:value', value + 1)">+</button>
    </div>`
}

// 父组件：监听事件
// <counter :value="count" @update:value="count = $event" />

3.3 插槽 —— 内容分发

插槽让父组件可以向子组件中注入自定义内容，实现更灵活的组件复用。有默认插槽、具名插槽、作用域插槽三种形式。

HTML 
<!-- 子组件定义插槽 -->
<template id="panel-tpl">
  <div class="panel">
    <div class="panel-header">
      <slot name="header">默认标题</slot>  <!-- 具名插槽 + 默认内容 -->
    </div>
    <div class="panel-body">
      <slot>默认内容</slot>  <!-- 默认插槽 -->
    </div>
  </div>
</template>

<!-- 父组件使用 -->
<panel>
  <template #header>用户管理</template>  <!-- # 是 v-slot 的简写 -->
  <p>这里是主体内容</p>
</panel>

Vue Router —— 路由配置、动态路由、导航守卫

难度：★★★☆☆

4.1 路由基础配置

Vue Router 是 Vue 官方的路由管理器，让单页应用拥有多页面般的导航体验。核心概念：路由表 → 匹配 → 渲染对应组件。

JS 
import { createRouter, createWebHashHistory } from 'vue-router'

// 1. 定义路由规则（路径 → 组件映射）
const routes = [
  { path: '/',        component: Home },
  { path: '/about',   component: About },
  { path: '/user/:id', component: User, props: true }, // 动态路由
]

// 2. 创建路由实例
const router = createRouter({
  history: createWebHashHistory(),  // Hash 模式（#/xxx）
  routes
})

// 3. 挂载到 App
app.use(router)
app.mount('#app')

// 模板中：
// <router-link to="/">首页</router-link>
// <router-view />  <!-- 路由匹配的组件渲染在这里 -->

4.2 动态路由与导航守卫

动态路由（/user/:id）匹配路径中的变量部分。导航守卫在路由切换前后执行逻辑（如权限检查、数据预加载）。

JS 
// 动态路由 —— 组件中访问参数
import { useRoute } from 'vue-router'
const route = useRoute()
console.log(route.params.id)   // 获取 /user/123 中的 '123'

// 全局前置守卫 —— 常用于登录检查
router.beforeEach((to, from, next) => {
  const isLoggedIn = localStorage.getItem('token')
  // 如果要去需要登录的页面但未登录，跳转到登录页
  if (to.meta.requiresAuth && !isLoggedIn) {
    next('/login')
  } else {
    next()   // 放行
  }
})

// 路由元信息
{ path: '/admin', component: Admin, meta: { requiresAuth: true } }
★
三种 History 模式：
1. createWebHashHistory() —— URL 带 #，无需服务器配置（推荐初学者）
2. createWebHistory() —— 干净的 URL，需要服务器配置 fallback
3. createMemoryHistory() —— SSR 场景使用

Pinia 状态管理 —— Store 定义、状态读写、Actions

难度：★★★☆☆

5.1 什么是 Pinia？

Pinia 是 Vue 官方推荐的状态管理库（Vuex 的继任者）。当多个组件需要共享数据时，把数据放在 Pinia Store 中，而不是在组件间层层传递。

JS 
import { defineStore } from 'pinia'

// 定义一个 Store（组合式风格，推荐）
export const useCounterStore = defineStore('counter', () => {
  // state —— 响应式数据
  const count = ref(0)
  const name = ref('Pinia')

  // getters —— 计算属性
  const doubleCount = computed(() => count.value * 2)

  // actions —— 修改状态的方法（同步/异步都支持）
  function increment() { count.value++ }
  function decrement() { count.value-- }
  async function fetchData() {
    const res = await fetch('/api/data')
    count.value = await res.json()
  }

  return { count, name, doubleCount, increment, decrement, fetchData }
})

5.2 在组件中使用 Store

JS 
import { useCounterStore } from './stores/counter'

export default {
  setup() {
    const counter = useCounterStore()  // 获取 store 实例

    // 读取 state（直接访问，自动响应式）
    console.log(counter.count)         // 0
    console.log(counter.doubleCount)   // 0（getter 自动计算）

    // 修改 state —— 三种方式
    counter.count++                    // ① 直接修改
    counter.$patch({ count: 10 })      // ② 批量修改（推荐）
    counter.increment()                // ③ 通过 action 修改（推荐）

    return { counter }
  }
}
✔
为什么用 Pinia 而不是 Vuex？ Pinia 没有 mutations（简化了），完整 TypeScript 支持，DevTools 更好用，且是 Vue 官方推荐。对于新项目，直接用 Pinia。
