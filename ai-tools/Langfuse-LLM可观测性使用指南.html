Langfuse：LLM 应用可观测性平台
从零到上手的完整指南

Langfuse 是目前最广泛采用的开源 LLM 工程平台（MIT 协议），为 LLM / Agent / RAG 应用提供 追踪（Tracing）、评估（Evaluation）、Prompt 管理（Prompt Management） 三大核心能力。本指南带你从概念、部署到写代码埋点，一步步跑通完整闭环。

追踪耗时 / Token / 成本 Prompt 版本管理 数据集回归测试 LLM-as-Judge 自动评估

什么是 Langfuse？

当你在构建一个 LLM 应用（聊天机器人、RAG 检索问答、多智能体系统等）时，通常会遇到这些问题：

  • 「这个回答为什么是错的？」—— 无法回放一次完整的调用链路。
  • 「哪个环节最慢？花了多少 Token？成本是多少？」—— 缺乏按步骤的耗时与成本统计。
  • 「改了一版 Prompt，效果到底变好还是变坏？」—— 没有回归测试。
  • 「Prompt 散落在代码里，谁在维护？」—— 没有集中管理和版本控制。

Langfuse 就是为解决这些问题而生的。它像一个「黑匣子记录仪 + 实验平台 + 内容管理系统」三合一：每一次用户交互都变成一条可以回放、分析、评分的 Trace。

Tracing / 追踪

记录每一次端到端调用，按 Span / Generation 展开，看清时间花在哪、错误出在哪、Token 与成本如何分布。

Evals / 评估

在数据集上运行实验，用 LLM-as-Judge 或自定义打分函数，量化模型 / Prompt 变更带来的质量变化。

Prompt 管理

像管理代码一样管理 Prompt：版本化、Label（prod/dev）、灰度发布、可回滚、与 Trace 关联度量。

为什么 LLM 需要专门的可观测性

传统后端 APILLM 应用
输出是确定性的，同样的输入同样输出输出非确定性，同 Prompt 不同时间不同答案
单次调用、单一服务多步骤工作流：检索 → 工具 → 路由 → 护栏 → 生成
日志量小、结构简单每一步都携带冗长而丰富的 I/O（Prompt、上下文、Token）
质量是客观布尔值（200 / 500）质量是主观的：「回答很糟」难以用一个布尔表达
成本由基础设施决定成本不透明，依赖 Token、模型、用户分群

没有可观测性，你就是在「盲飞」。Langfuse 把开发从「猜测 + 祈祷」变成「观察 + 测量 + 迭代」。

核心概念

7 个概念

掌握下面 7 个概念，你就掌握了 Langfuse 的全部用法。

Trace / Observation 层级关系
Trace一次端到端交互（如一次用户提问）
Span检索文档 · 50ms
Span工具调用 · 120ms
GenerationLLM 调用 · 1.8s · 1234 tokens
Generation（嵌套）子 LLM 调用
Score打分：helpfulness / correctness…

1Project / 项目

代表一个应用或产品。项目内通常划分 dev、staging、prod 等环境，每个环境用不同的 API Key，避免测试数据污染生产。

2Trace / 轨迹

一次端到端交互，通常对应用户一次请求。UI 中以时间线 / 树状图呈现，可以下钻查看每一步实际发生了什么。

3Span / 步骤

Trace 内的一个步骤：数据库查询、检索操作、工具调用、API 请求，或你自己埋点的自定义逻辑。用于定位「时间花在哪」。

4Generation / 生成

特指一次 LLM 调用，是 Span 的特殊类型，额外记录 model、input/output、usage（Token + 成本）。

5Score / 分数

附加在 Trace 或 Generation 上的标签或指标：helpfulness: 0-1、correctness、passes_policy: bool 等。来源：人工标注、评估模型、程序化检查。

6Dataset / 数据集

一组测试用例，通常从真实 Trace 中提炼。每行含 input、expected_output、metadata。用于对新 Prompt / 模型做回归测试。

7Prompt / 提示词

一个 Prompt CMS：集中存储、带版本、带 Label（如 production、latest）、可回滚。代码通过 langfuse.get_prompt("name") 拉取，而非硬编码文本。每次 Prompt 变更都能和线上 Trace / 评估关联，量化效果。

整体架构

理解架构有助于你在自托管时正确配置。核心是「应用异步上报 → 队列缓冲 → ClickHouse 存储 → UI 查询」。

Docker 自托管（本地体验）

前提：安装 Docker Desktop（Windows / Mac 自带 docker compose）并已安装 git。

1
克隆仓库并启动
# 克隆官方仓库（含 docker-compose.yml）
git clone https://github.com/langfuse/langfuse.git
cd langfuse

# 启动数据库与 Langfuse 服务（首次会拉取镜像，需几分钟）
docker compose up -d
2
访问 UI 并创建账号
# 浏览器打开
http://localhost:3000

# 首次访问点击 Sign up 创建账号，随后创建 Organization 和 Project

创建完 Project 后，页面会给出 public key 与 secret key，记下来，后续 SDK 上报要用。

3
SDK 指向本地地址
# 环境变量里把 BASE URL 指向本地实例
export LANGFUSE_BASE_URL="http://localhost:3000"
注意：默认 docker compose 用于本地测试，数据库不持久、密钥不保密，不适合生产。生产环境请参考官方部署指南（K8s / Helm / Terraform），并务必修改 docker-compose 中所有 # CHANGEME 标记的密码。升级：docker compose up --pull always。

安装与配置（Python SDK）

Langfuse 支持 Python、JS/TS 以及 OpenTelemetry 原生集成。本指南以 Python SDK v3（基于 OpenTelemetry）为主。

pip install langfuse

配置（推荐用环境变量）

# .env 文件
LANGFUSE_PUBLIC_KEY="pk-lf-..."
LANGFUSE_SECRET_KEY="sk-lf-..."
# 默认 https://cloud.langfuse.com；自托管改成你的地址；US 区用 https://us.cloud.langfuse.com
LANGFUSE_BASE_URL="https://cloud.langfuse.com"
获取客户端：SDK v3 用 get_client() 自动读取上述环境变量。若仍用经典 API（v2），则是 Langfuse(public_key=..., secret_key=..., host=...)，环境变量名为 LANGFUSE_HOST。二者别混用。

第一个 Trace（10 分钟上手）

用上下文管理器记录一次 LLM 调用，运行后立即在 UI 看到结果。

from langfuse import get_client

langfuse = get_client()  # 读取 LANGFUSE_* 环境变量

# 外层 Span：一次处理请求
with langfuse.start_as_current_observation(
    as_type="span", name="process-request"
) as span:
    span.update(input="用户的原始输入")

    # 嵌套 Generation：一次 LLM 调用
    with langfuse.start_as_current_observation(
        as_type="generation",
        name="llm-response",
        model="gpt-4o",
    ) as gen:
        # 你的真实 LLM 调用逻辑写在这里
        answer = "你好，这是模型回复"
        gen.update(output=answer)

# 短生命周期应用（脚本、Serverless）需手动 flush 上报
langfuse.flush()

print("done")

运行后打开 Langfuse UI，会看到一条名为 process-request 的 Trace，点进去能看到嵌套的 llm-response Generation，包含 input、output、model、耗时等信息。

三种埋点方式

① 装饰器 @observe（最省事）

from langfuse import observe

@observe()
def answer_question(question: str) -> str:
    # 函数体自动成为一个 Span，入参/返回值自动记录
    ...
    return answer

answer_question("Langfuse 和 LangSmith 有什么区别？")

嵌套调用多个被 @observe 装饰的函数，会自动形成父子层级。

② 上下文管理器（推荐，控制力强）

with langfuse.start_as_current_observation(
    as_type="span", name="retrieval"
) as span:
    docs = retrieve(question)
    span.update(output=[d.metadata for d in docs])

③ 手动创建（需手动 end）

gen = langfuse.start_observation(
    name="llm-call", as_type="generation", model="gpt-4o"
)
# ... 你的逻辑 ...
gen.update(output=answer, usage={...})
gen.end()  # 手动结束时务必调用

附加 Trace 属性：用户 / 会话 / 标签

from langfuse import get_client, propagate_attributes

langfuse = get_client()

# 在该上下文内，所有 Span 自动带上 user_id / session_id / tags
with propagate_attributes(user_id="u_123", session_id="s_456", tags=["prod"]):
    with langfuse.start_as_current_observation(as_type="span", name="step"):
        ...

框架集成（零侵入 / 低侵入）

Langfuse 提供 100+ 集成，覆盖 OpenAI、LangChain、LangGraph、LlamaIndex、Vercel AI SDK 等。这里给出两个最常用的例子。

OpenAI SDK

from langfuse.openai import openai  # 替换为标准 client，自动追踪

completion = openai.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "你好"}],
    langfuse_prompt="my-prompt",  # 可选：关联 Prompt
)

LangChain（CallbackHandler）

from langfuse.langchain import CallbackHandler

langfuse_handler = CallbackHandler()  # 读取环境变量

# 在 invoke 时传入 callbacks 即可
chain.invoke(
    {"question": "..."},
    config={"callbacks": [langfuse_handler]},
)

LangChain / LangGraph 的每个 chain / node / tool 调用会自动展开成嵌套的 Span 与 Generation，无需手动埋点。

Prompt 管理

把 Prompt 从代码里抽出来，放进 Langfuse 做版本化。核心 API：create_prompt、get_prompt、compile。

创建 Prompt（在 UI 或代码中）

from langfuse import Langfuse

langfuse = Langfuse()

langfuse.create_prompt(
    name="movie-critic",
    prompt="你是一名影评人。请评价电影：{{movie}}",
    labels=["production"],  # 直接挂到生产 label
)

拉取并使用（带缓存）

from langfuse import get_client

langfuse = get_client()

# 拉取 production 版本，缓存 300 秒（减少网络往返、提升性能）
prompt = langfuse.get_prompt("movie-critic", cache_ttl_seconds=300)

# 用变量渲染最终 Prompt；variable 是 {{movie}} 的占位值
final_prompt = prompt.compile(movie="Dune 2")

# 把 Prompt 版本与本次 Generation 关联，用于后续度量
with langfuse.start_as_current_observation(
    as_type="generation", name="review", model="gpt-4o", prompt=prompt
) as gen:
    answer = call_llm(final_prompt)
    gen.update(output=answer)
Label 机制：每个 Prompt 有多个版本，每个版本可打 Label（如 production / latest / dev-v2）。上线 = 把新版本挂到 production label，回滚 = 把 label 指回旧版本，全程不改代码。UI 中 Prompt 详情页有「Metrics」页签，可以看到每个版本关联的 Trace 数量与评分。

数据集与实验（回归测试）

Dataset 是「测试用例集合」，通常从线上真实 Trace 里挑选。实验 = 用新 Prompt / 新模型在 Dataset 上跑一遍并打分，判断是改进还是回退。

from langfuse import Langfuse

langfuse = Langfuse()

# 1. 拉取数据集
dataset = langfuse.get_dataset("qa-test-set")

# 2. 遍历每条测试用例
for item in dataset.items:
    question = item.input["question"]
    expected = item.expected_output  # 参考答案

    # 用当前（新）Prompt 跑一遍
    output = run_pipeline(question)

    # 3. 打分并写回
    langfuse.score(
        trace_id="...",
        name="correctness",
        value=0.92,
        comment="...",
    )

更推荐使用 langfuse.run_experiment()（需配合 LLM-as-Judge evaluator），它会把「实验运行」作为一个整体关联到数据集上，UI 中可对比多次实验的平均分，并支持接入 CI 做自动化回归。

评估 · LLM-as-Judge

评分（Score）可以来自三种来源，Langfuse 统一在 UI 中展示、筛选、聚合。

① 人工标注

在 UI 标注界面或内部工具里打分。

② LLM-as-Judge

用一个模型给另一个模型的输出打分。

③ 程序化检查

正则、单元测试、业务规则（如是否命中敏感词）。

LLM-as-Judge 示例（离线评估管线）

# 概念性示例：用 gpt-4o 作为裁判，给每个回答打相关性分
def judge(question, answer, reference):
    judge_prompt = """
    问题：{question}
    参考答案：{reference}
    模型回答：{answer}
    请从 0 到 1 打分，评估回答的相关性与正确性。只输出数字。
    """
    score = call_llm(judge_prompt)
    return float(score)

# 对每条用例打分并写回 Langfuse，形成可对比的质量曲线
Langfuse 还提供开箱即用的 LLM-as-Judge Evaluator 模板（如 relevance、helpfulness、hallucination、toxicity），可直接在 UI 或 SDK 中配置，避免自己写裁判 Prompt。

UI 使用指南

Traces 页

  • 列表视图：按时间 / 环境 / 用户 / 名称 / 评分筛选
  • 点击进入时间线视图，看每个 Span 的耗时占比
  • 点开 Generation 查看完整 input/output、token 用量、成本

Dashboard 页

  • 观测总量、平均耗时、Token 总消耗、总成本

  • 从真实 Trace「添加到数据集」一键建用例

  • 直接在 UI 上编辑并发布新版本（不改代码）

最佳实践

1
按「架构」设计 Trace，而非单次调用

把 RAG 拆成 retrieval / rerank / generate 多个 Span；把多智能体拆成 orchestrator + 各 specialist，问题才能定位到具体环节。

2
环境隔离用不同 API Key

dev / staging / prod 各自独立 Project 或环境，避免测试 Trace 污染生产指标。

3
做好数据脱敏（Data Masking）

Prompt 里常含用户隐私，上报前用正则 / 掩码策略过滤 PII（邮箱、手机号、身份证）。

4
Prompt 一律走版本管理，别硬编码

配合 get_prompt 缓存 + Label 灰度，让 Prompt 变更可观测、可回滚。

5
把评估接进 CI，形成回归门禁

每次 Prompt / 模型变更自动跑数据集，分数下降即阻断合入（可结合官方 experiment-action）。

常见问题（FAQ）

Langfuse 和 LangSmith 有什么区别？

两者功能高度重叠（追踪/评估/Prompt 管理）。核心区别：Langfuse 完全开源（MIT）可自托管，无数据锁定，社区更大、集成更开放（OTel 原生）；LangSmith 是 LangChain 官方产品，与 LangChain 生态深度绑定，但核心不开源、主要为 SaaS。看重数据自主与开源选 Langfuse。

Python SDK v2 和 v3 我该用哪个？

新项目用 v3（基于 OpenTelemetry，get_client() + @observe）。旧代码里常见的 langfuse.trace() / trace.generation() 是 v2 经典 API，仍可用但注意版本差异（v2 用 LANGFUSE_HOST，v3 用 LANGFUSE_BASE_URL）。

为什么运行后 UI 里看不到 Trace？

最常见三个原因：① 脚本 / Serverless 里忘了 langfuse.flush()；② 环境变量名或 BASE_URL 不对（自托管要指向 http://localhost:3000）；③ Key 属于另一个 Project。先检查这三处。

上报会不会拖慢我的应用？

不会。SDK 默认异步批量上报，追踪不阻塞业务逻辑。长驻进程（Web 服务）由后台线程定时发送；短生命周期脚本需显式 flush() 确保退出前发送完毕。

免费额度是多少？自托管收费吗？

Cloud 免费版 50k 观测/月（含追踪/评估/Prompt 管理核心功能）。自托管版 MIT 协议，全部核心功能免费，仅需自担服务器成本。企业级功能（SSO、审计日志等）才需付费。
