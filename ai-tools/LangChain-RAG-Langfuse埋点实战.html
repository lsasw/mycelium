埋点原理

三层埋点，各司其职

这份示例同时演示了 Langfuse 的三层埋点方式。从下到上，从「自动」到「语义」再到「上下文」，组合起来就是一条信息完整的 Trace。

① 自动埋点 · CallbackHandler

把 handler 注入 LangChain 调用的 config，框架内部的 Retriever / Embedding / LLM 事件会自动映射成 Span 与 Generation，零侵入。这是最省事的埋点方式。

chain.invoke(..., config={"callbacks": [handler]})

② 语义埋点 · @observe

用装饰器把业务函数圈成有名字的 Span，Trace 的层级结构就由你的代码结构自然生成：ask → retrieve → generate。

@observe(name="rag.retrieve")
def retrieve(question): ...

③ 上下文增强 · get_client()

挂 user_id / session_id / metadata，并拿到 Trace 直链返回给调用方，方便从应用端直接跳转排查。

langfuse = get_client()
langfuse.update_current_trace(user_id=..., session_id=...)
url = langfuse.get_trace_url()
埋点层写法你在 UI 里看到什么
自动
CallbackHandler		 from langfuse.langchain import CallbackHandler，再在 invoke(..., config={"callbacks": [...]}) 注入 Retriever / Embedding / Generation 节点，含召回文档、Token 用量、估算成本、延迟
语义
@observe		 @observe(name="rag.retrieve") 装饰业务函数，嵌套结构即 Trace 树 业务命名的 Span：rag.ask → rag.retrieve → rag.generate
上下文

进阶技巧

从「能跑」到「生产可用」
FastAPI 用同步 def

被 @observe 装饰的端点建议用同步 def 而非 async def，避免上下文传播与事件循环冲突的坑（示例 app.py 已这样做）。

CLI / 批处理记得 flush()

Trace 是异步上报的，短生命周期脚本会在数据发出前退出。示例 main.py 末尾调了 get_client().flush()，别删。

自托管平台版本要够新

Python SDK v3 要求自托管平台 ≥ 3.125.0，否则静默失败或报错。升级镜像后记得重新拉取。

数据脱敏

metadata 别放明文密钥 / 手机号等敏感字段；生产环境建议在 SDK 侧配置 masking 规则，或在上报前统一脱敏。

采样控制成本

高流量场景可只采样部分请求（如 10%），或只对失败 / 慢请求全量上报，避免观测成本反超模型成本。

与 Prompt 管理联动

把 RAG 的 system prompt 放进 Langfuse Prompt 管理（带版本与 Label），LLM 调用时通过 metadata 关联，Trace 里直接看到用的是哪个 Prompt 版本。

常见问题

排错优先看这里
跑完了但 Langfuse 里看不到 Trace？

按顺序排查：① .env 是否已加载（打印 os.getenv("LANGFUSE_PUBLIC_KEY") 确认）；② LANGFUSE_BASE_URL 是否指向正确的云区域或自托管地址；③ 自托管平台版本是否 ≥ 3.125.0；④ CLI 脚本是否调用了 flush()；⑤ 看终端是否打印 langfuse 相关错误日志。

同一个请求出现两条 Trace（重复）？

通常是因为 handler 被重复注入：同一请求在 with_config 和 invoke 的 config 里各放了一次 handler。handler 全局只初始化一个，只在一个层级注入即可。

ModuleNotFoundError: No module named 'langfuse.langchain'？

版本不对。确认安装的是 v3：pip install "langfuse>=3.0.0"，然后使用 from langfuse.langchain import CallbackHandler。若项目还在用 v2，改为 from langfuse.callback import CallbackHandler，并注意 v2 的 Langfuse() 初始化方式与 LANGFUSE_HOST 变量。

LANGFUSE_HOST 和 LANGFUSE_BASE_URL 用哪个？

v3 首选 LANGFUSE_BASE_URL；LANGFUSE_HOST 是旧名，仍兼容但会告警（两者都设置时以 BASE_URL 为准）。云版 EU 用 https://cloud.langfuse.com，US 用 https://us.cloud.langfuse.com，自托管用你自己的实例地址。

为什么示例里 retrieve 也要传 callbacks？

自动埋点只对「注入了 handler 的调用」生效。直接调 retriever.invoke(q) 而不传 config，LangChain 不会产生观测事件；传了之后，Retriever Span 和内部的 Embedding Span 才会被采集并嵌套到当前 @observe 上下文里。

@observe 的 Span 名和函数名不一致？

用 @observe(name="rag.retrieve") 显式命名即可；不传 name 时默认用函数名。建议按「模块.动作」命名（如 rag.retrieve / rag.generate），在 Trace 列表里更易检索。
